# experiments: one folder per study

Each folder holds one study's driver, its analysis steps and a README with every command. The table gives each study's
place in the paper (figure numbers of the paper's draft; the paper labels that `just results` re-makes are in the top README, "Reproduce the paper"; "exploratory": not in the paper) and its smallest run: the cheapest command that exercises it end to end, at SF0.1 or on the archived results. Times are on
**A**, a 16-core AMD EPYC 7302P with SATA SSDs, and **B**, a 40-core node whose data was on a hard disk, as in
[run/README.md](../run/README.md#install-versions-memory-disk); "-" means not timed on that machine. Every run here assumes the top README's Getting Started (`just setup`, `just smoke`).

| study | in the paper | what it measures | smallest run | time on A / B | needs beyond Getting Started |
|---|---|---|---|---|---|
| [core_suite](core_suite/README.md) | exploratory | per query and format: KV operations (SEEK, GET, NEXT), bytes read by lane, warm and cold latency, with figures | `run/kvstats.sh --sf 0.1` | 2.5 min / 3.1 min | `just fetch-dataset ldbc=0.1` |
| [engine_fidelity](engine_fidelity/README.md) | Fig 2; the fidelity numbers (section 4.2) | does the evaluator reproduce a real engine's KV counts on that engine's own plan (reads and writes) | `write_fidelity.py --sweep <the archived sweep> --capture <the formats' write counts>` (the write side; the counts: `kvcost measure --dataset ldbc=0.1 --family writes dgraph-c512k nebula arangodb`) | under 1 s / under 1 s | `just fetch-results` and `just fetch-dataset ldbc=0.1`; the read side also the three databases, built and loaded (`engines/README.md`: "Needs", "Run it") |
| [job](job/README.md) | Table 2; Fig 9 (JOB's counts) | the IMDb / JOB workload's counts on the nine uniform layouts and the three engine formats | `run-job-counts-chain.sh sample1pct` | 41 min / - (after the data; 31 min with the faster grid check, computed) | the IMDb data (`ensure.py --tag sample1pct`: a 1.26 GB download, 3 min, 11.6 GB) |

The timed (latency) drivers bind the evaluator to one NUMA node and need `numactl`:
`sudo apt-get update && sudo apt-get install -y numactl`.

The commands in full, and what a pass prints, are in each study's README. Several studies read the same sf0.1 grid
(`kvcost measure --dataset ldbc=0.1 --workload i01 Sp-Sp Co-Co Ch1k-Ch1k Ch4k-Ch4k Ch16k-Ch16k Ch64k-Ch64k Ch256k-Ch256k` and `--family microbench` on the same seven, then `kvcost compose
--dataset ldbc=0.1`): it is measured once and reused.
